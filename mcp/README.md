# @openbiox/bizard-mcp

A [Model Context Protocol](https://modelcontextprotocol.io) (MCP) server for
the [Bizard](https://openbiox.github.io/Bizard/) biomedical visualization
atlas ([GitHub](https://github.com/openbiox/Bizard)). It serves the
full chart lifecycle over MCP: **query** (bilingual search across 800+ chart
tutorials), **use** (runnable code, dependencies, data URLs, and structured
adaptation guidance the host AI executes), **cite** (BibTeX/DOI metadata with
license notice), and **contribute** (template-checked issue/PR submission that
degrades gracefully by environment). Content comes from a bundle generated by
CI from the same sources as the website and `SKILL.md`, so all three never
drift. The server never executes plotting code — the host AI does.

## Quickstart

No install at all — connect to the [public hosted instance](#public-hosted-instance-no-install-required)
(pure Streamable HTTP, works with any MCP-capable agent).

Local, stdio (works offline — an npm-shipped content snapshot backs everything up):

```bash
npx @openbiox/bizard-mcp
```

Register the local server with Claude Code:

```bash
claude mcp add bizard -- npx @openbiox/bizard-mcp
```

Hosted instance with Claude Code:

```bash
claude mcp add --transport http bizard http://biotree.top:38123/bizard-mcp/mcp
```

## Tools

| Tool | Purpose |
|------|---------|
| `bizard_search` | Bilingual weighted search over the chart gallery; adjacent-category suggestions on zero hits |
| `bizard_list_categories` | All 36 chart categories with per-category chart counts (bilingual names where available) |
| `bizard_get_tutorial` | Chart metadata: packages, example-data URLs, available languages, tutorial link |
| `bizard_get_code` | Runnable tutorial code with package list, example-data URLs, and license notice |
| `bizard_adapt_guidance` | Data-shape checks, dependency prep, parameter mapping, failure modes, alternatives |
| `bizard_cite` | Bizard paper + tutorial citation (bibtex/text/json) with CC-BY-NC-4.0 license notice |
| `bizard_contribute_check` | Validate a draft against the contribution template; preview points (issue #4) |
| `bizard_contribute_submit` | Submit as issue/PR via user credentials, or degrade to draft + deep-link |

Prompts: `recommend`, `adapt`, `troubleshoot`, `contribute`.
Resources: `bizard://catalog`, `bizard://tutorial/{chartId}`, `bizard://llms-txt`.

## Deployment

One package, two transports:

- **Local (stdio, default)**: `npx @openbiox/bizard-mcp`. Full capability; contribution runs at level 1/2 when local credentials exist.
- **Hosted (Streamable HTTP)**: `npx @openbiox/bizard-mcp --http`. Port via `BIZARD_HTTP_PORT` (default 3000). Anonymous, stateless — each POST to `/mcp` gets a fresh transport. Per-IP token-bucket rate limit (60 req/min; 429 with `Retry-After`). Contribution runs at level 3 (no credentials on the server).

### Public hosted instance (no install required)

A community instance is deployed by the Bizard team. It speaks standard
Streamable HTTP, so **any MCP-capable agent** can connect — Claude Code,
Cursor, Cline, Windsurf, VS Code Copilot Chat, custom agent frameworks —
with no local install. It may also be faster than an npm-based setup for
users in mainland China.

Most MCP clients accept a JSON server entry:

```json
{
  "mcpServers": {
    "bizard": { "type": "http", "url": "http://biotree.top:38123/bizard-mcp/mcp" }
  }
}
```

Claude Code accepts it from the CLI too:

```bash
claude mcp add --transport http bizard http://biotree.top:38123/bizard-mcp/mcp
```

Same anonymous, stateless, rate-limited behavior as the self-hosted HTTP
mode; contribution runs at level 3 (the instance holds no credentials).

## Contribution credential degradation

`bizard_contribute_submit` probes the environment on every call and states
which level it used — never silently failing:

| Level | Condition | Behavior |
|-------|-----------|----------|
| 1 | `gh` CLI installed and logged in | Creates the issue as your GitHub user (PR submission is planned for a future release) |
| 2 | No `gh`, but `GITHUB_TOKEN` set | GitHub API submission, limited by token scope |
| 3 | Neither (typical for hosted) | Returns formatted draft + pre-filled `issues/new?title=&body=` deep-link |

The server itself holds zero credentials. User free text is truncated
(single field ≤ 4000 chars) before being assembled into issue bodies.

## Privacy

Usage feedback is local-only, anonymous, and never networked:

- Appended to `~/.cache/bizard-mcp/usage-log.jsonl` as
  `{ ts, event, chartId, language, queryHash }` — `queryHash` is the first
  8 hex chars of the query's SHA-256 (irreversible).
- Set `BIZARD_USAGE_LOG=off` to disable entirely; set it to a path to relocate
  the log.
- No server-side telemetry, ever.

## Development

```bash
npm install
npm run build:bundle   # regenerate src/snapshot/ (works from mcp/ — defaults are repo-root-relative)
npm test               # vitest suite
npm run coverage       # gate: statements ≥ 80%
npm run build          # tsc + copy snapshot into dist/
```

`npm run build:bundle` shells out to `../.github/scripts/build-bundle.py`,
whose CLI defaults resolve against the repository root regardless of the
current working directory. Run it from `mcp/` via the npm script, or run the
Python script from anywhere with an explicit `--out`. CI:
`.github/workflows/mcp-ci.yml` (Python bundle tests, node tests + coverage
gate, stdio smoke) and `.github/workflows/mcp-bundle.yml` (rebuilds
`files/mcp/bundle.json` + `llms.txt` on content pushes, which the site ships
via `_quarto.yml` resources).
